# ران‌بوک — بکاپ و بازیابی (backup-restore)

> **منبع:** سند مادر v2.5 فصل ۹.۸. بکاپ بدون بازیابیِ آزموده فقط یک امیدواری مستند است.

## اهداف عددی

| شاخص | هدف |
|---|---|
| RPO | ≤ ۱۵ دقیقه (WAL archiving حداقل هر ۱۵ دقیقه یا streaming + PITR) |
| RTO — خرابی VPS با دیسک سالم | ≤ ۱ ساعت (ری‌استارت سرویس‌ها + PITR) |
| RTO — از دست رفتن کامل سایت | ≤ ۴ ساعت (restore کامل از آرشیو off-site) |
| فرکانس | روزانه + WAL پیوسته |
| ماندگاری | ۳۰ روزانه + ۱۲ ماهانه؛ رمزنگاری‌شده؛ خارج سرور اصلی (off-site، S3 سازگار) |
| فایل PDF | همگام‌سازی روزانه به off-site |
| آزمون restore | ماهانه روی staging + ثبت در audit_logs |

## چک‌لیست verify هر restore (آزمایشی یا واقعی)

- [ ] شمار بارنامه‌ها مطابق آخرین گزارش روزانه
- [ ] شناسهٔ آخرین payment ثبت‌شده مطابق انتظار
- [ ] دانلود موفق یک PDF نمونه (از مسیر endpoint محافظت‌شده)
- [ ] یکپارچگی زنجیرهٔ audit (تُرپل لنگر off-site با رأس زنجیره مطابقت کند)

> restore بدون verify یعنی تئاتر.

## روند بازیابی کامل (از دست رفتن سرور)

```bash
# ۱. سرور جدید + Docker + کلیدهای env (کلید AES درگاه و رمز بکاپ از کپی امن مشتری)
# ۲. restore پایگاه از آخرین full + بازیابی WAL تا نقطهٔ هدف (PITR)
# ۳. همگام‌سازی فایل‌های PDF از off-site
# ۴. اجرای tools/migrate-all.ts --org <org>  (تطبیق نسخهٔ schema)
# ۵. بالا آوردن web + worker؛ اجرای چک‌لیست verify + دود-تست deploy.md
```

## نکات

- کلید رمزنگاری بکاپ مشتری با کلید خودِ مشتری رمز می‌شود و هرگز به سرورهای توسعه‌دهنده منتقل نمی‌شود.
- هشدار «آخرین بکاپ موفق >۲۶ ساعت» → اعلان TECH_ADMIN.
- دسترسی فنی به زیرساخت مشتری فقط با حساب شخصی ثبت‌شده از VPN/SSH و بازهٔ محدود؛ همهٔ دستورها لاگ می‌شوند.
