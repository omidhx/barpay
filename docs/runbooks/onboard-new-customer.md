# ران‌بوک — استقرار مشتری جدید (onboard-new-customer)

> **منبع:** سند مادر v2.5 فصل ۹.۷ و ۹.۹. مدل: کد مشترک، استقرار + دیتابیس + دامنهٔ جدا.

## چک‌لیست راه‌اندازی نمونهٔ جدید

- [ ] زیردامنه/دامنهٔ مشتری + TLS (Nginx)
- [ ] VPS یا پارتیشن جدا + Docker + PostgreSQL 16
- [ ] `.env` اختصاصی: DB_URL، کلید AES-256-GCM درگاه، اعتبارنامهٔ پیامک (فراز/ملی)، سقف روزانهٔ پیامک
- [ ] اجرای `tools/migrate-all.ts --org <new>` از صفر (نسخهٔ schema ثبت شود در registry)
- [ ] ساخت سازمان + کاربر OWNER اول (ورود با رمز موقت + الزام تغییر رمز + 2FA)
- [ ] تنظیمات سازمان: مضرب گرد شدن (پیش‌فرض ۵۰٬۰۰۰)، افزودنی، **retention (پیش‌فرض KEEP_10Y تا انتخاب مدیر)**، سرویس پیامک
- [ ] نگاشت ستون‌های اکسل (`excel_column_mappings`) با فایل نمونهٔ واقعی مشتری
- [ ] ثبت قالب تعهدنامه (DRAFT → بعد از تأیید حقوقی ACTIVE) + تنظیم `COMMITMENT_ENFORCEMENT=OFF` در تولید تا تأیید
- [ ] پیکربندی درگاه (پیشنهاد: واسط زرین‌پال/زیبال برای شروع؛ SANDBOX در staging؛ «تست اتصال»)
- [ ] ثبت کارت‌های واریز + پیش‌نمایش «نمای راننده»
- [ ] فعال‌سازی بکاپ روزانه + WAL + آرشیو off-site + **آزمون restore اولیه**
- [ ] دود-تست: import نمونه → تطبیق PDF → لینک آزمایشی → OTP → تعهدنامه (SHADOW) → پرداخت sandbox → دانلود

## قواعد

- هر انشعاب اختصاصی از کد باید مستند و موقت باشد؛ تغییرات مشترک به بالا (upstream) برمی‌گردند.
- مدارک شاپرک (ای‌نماد + کد رهگیری مالیاتی) پیش‌نیاز فعال‌سازی LIVE درگاه است.
- حساب فنی روی زیرساخت مشتری: شخصی، ثبت‌شده، فقط VPN/SSH، بازهٔ محدود، لاگ کامل.
