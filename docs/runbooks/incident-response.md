# ران‌بوک — واکنش به حادثه (incident-response)

> **منبع:** سند مادر v2.5 فصل ۹.۸ و ۱۱. هدف: تشخیص سریع، محدودسازی، بازیابی، ثبت.

## سطوح

| سطح | مثال | واکنش اولیه |
|---|---|---|
| P0 | از دست رفتن داده / نشت امنیتی / درگاه همهٔ تراکنش‌ها را رد می‌کند | توقف انتشار + مالک + backup-restore |
| P1 | پیامک هر دو سرویس قطع / صف عمیق / API 5xx >۱٪ | engaged فنی + runbook مربوطه |
| P2 | نرخ شکست درگاه >۱۰٪ / پیامک ناموفق >۱۰٪ | اعلان خودکار + بررسی در ساعات کاری |

## هشدارهای خودکار موجود (سنسورها)

عمق صف job >۵ دقیقه · API 5xx >۱٪ در ۵ دقیقه · تحویل پیامک <۹۰٪ در ۱ ساعت ·
آخرین بکاپ >۲۶ ساعت · شکست init/verify درگاه >۱۰٪ در ۱ ساعت · سقف پیامک (۸۰٪/۱۰۰٪) ·
ردیف‌های UNKNOWN درگاه باقی‌مانده >۲۴ ساعت (STILL_UNKNOWN → اعلان سرپرست).

## الگوی پاسخ

1. **تشخیص:** correlationId رویداد را از پاسخ/لاگ بگیرید — همهٔ لاگ‌های همان درخواست با آن زنجیر می‌شوند.
2. **محدودسازی:** اگر موضع مشکوک است، انتشار همان سازمان hold می‌شود (سایر سازمان‌ها مستقل‌اند — مزیت استقرار جدا).
3. **بازیابی:** runbook مربوطه (deploy / backup-restore / rollback / sms-providers).
4. **ثبت:** هر حادثه + اقدامات + نتیجه در audit_logs و گزارش post-mortem (ریشه، نه مقصر).

## حادثه‌های خاص

- **تراکنش UNKNOWN درگاه:** هرگز FAILED تلقی نکنید؛ تا ۲۴ ساعت استعلام خودکار؛ راننده پیام «در حال بررسی» می‌بیند و پرداخت دوم قفل است؛ ماندگار → پیگیری دستی با ارائه‌دهنده (payload کامل در `gateway_transactions`).
- **callback جعلی مشکوک:** رویداد امنیتی ثبت شده (`GATEWAY_CALLBACK_INVALID`)؛ نیازی به اقدام مالی نیست — نتیجه فقط از وریفای می‌آید.
- **دستکاری لاگ مشکوک:** تُرپل لنگر off-site را با رأس زنجیرهٔ audit مقایسه کنید (حداکثر پنجرهٔ ۱۵ دقیقه).
- **قطع هر دو سرویس پیامک:** پیام‌ها صف می‌شوند؛ دعوت‌های جدید به تعویق؛ اپراتورها تماس تلفنی؛ عملیات مالی سامانه دست‌نخورده.
- **سوءاستفادهٔ OTP (قفل‌های پیاپی):** شماره با `OTP_MOBILE_SUSPENDED` تعلیق و اعلان اپراتور؛ بازگشایی فقط با تأیید تلفنی.

## ارتباط

- راننده: پیام فارسی کوتاه + شمارهٔ پشتیبانی + کد پیگیری؛ هرگز جزئیات فنی.
- اپراتور: `human_message` + `action_hint` (مثلاً «پیامک به راننده نرسید؛ تلفن خاموش بود. تماس بگیرید.»).
- TECH_ADMIN/مدیر: اعلان داخلی + پنل سلامت.
