# راهنمای UI/UX و RTL — ui-ux-rtl-guidelines

> **منبع:** سند مادر v2.5 فصل ۸ و ۱۶.۵/۱۶.۶. محصول فارسی، **RTL-first**،
> موبایل‌محور برای راننده. مخاطب راننده: کم‌فناور، پشت فرمان، نور آفتاب، گوشی اقتصادی.

## قواعد سراسری

- `dir="rtl"` روی ریشه؛ فونت **Vazirmatn**؛ اعداد مبلغ با جداکنندهٔ هزارگان فارسی؛ تاریخ شمسی برای نمایش.
- ورودی‌های عددی (جست‌وجو، OTP، مبلغ دستی) از تابع واحد `normalizeDigits` عبور می‌کنند (تبدیل ارقام فارسی/عربی → لاتین) — بدون این، دموی مشتری روی کیبورد فارسی می‌شکند.
- پیام وضعیت همراه متن، نه فقط رنگ (دسترسی‌پذیری)؛ کنتراست متن ≥۴.۵:۱ و متن حساس ≥۷:۱ (WCAG AAA — خوانایی در نور کابین).
- دیالوگ تأیید برای هر عملیات حساس با خروجیه اطلاعات (شمارهٔ بارنامه، نام، مبلغ قدیم/جدید، دلیل) — الگوی ۸.۷.
- پیام نتیجهٔ هر عملیات شامل کد رویداد audit (استناد در پشتیبانی)؛ خطا همیشه: کد پایدار + پیام فارسی + اقدام پیشنهادی + correlationId.
- خطای فنی/stack trace هرگز به راننده نمایش داده نمی‌شود.
- polling سبک ۳۰ ثانیه‌ای برای صف‌های زنده (WebSocket در MVP رد شده)؛ فیلترها در URL (قابل اشتراک).

## پورتال راننده — مسیر چهارگامی (ترتیب نسخهٔ ۲.۵: تعهدنامه پیش از پرداخت)

```text
۱. مشاهده اطلاعات  →  ۲. پذیرش تعهدنامه و امضا  →  ۳. پرداخت (درگاه/کارت‌به‌کارت)  →  ۴. دریافت بارنامه
```

- **گام فعلی از سرور محاسبه می‌شود** (فاز مشتق) — نه state محلی؛ رفرش/قطعی اینترنت/بازگشت گام را خراب نمی‌کند.
- پیش‌نویس فرم پرداخت در localStorage؛ فایل رسید در حافظهٔ صفحه تا اتصال مجدد.
- قفل دکمه پس از ثبت (جلوگیری از ارسال دوباره با چند لمس) + `Idempotency-Key` سمت سرور.
- در حالت مابقی: صفحهٔ پرداخت با برچسب «مابقی مبلغ بارنامه» — گام تعهدنامه حذف می‌شود.
- قطع نشست/بستن صفحه → پیام «از همان لینک پیامک‌شده دوباره وارد شوید و کد جدید بگیرید» — راننده هرگز از اول شروع نمی‌کند.

### صفحهٔ اول (قبل از احراز هویت)
فقط: نام شرکت، توضیح کوتاه، دکمهٔ دریافت کد، شمارهٔ پشتیبانی — **هیچ اطلاعات مالی/هویتی قبل از OTP**.

### پس از ورود
بالای صفحه: شمارهٔ بارنامه، اطلاعات ضروری، مبلغ و **واحد کاملاً واضح (ریال)**، وضعیت، اقدام بعدی. زیر مبلغ ریز اختیاری: «مبلغ پایه (گردشده) + مبلغ افزودنی».

### گام ۲ — تعهدنامه
متن رندرشدهٔ سمت سرور (متغیرها جای‌گذاری‌شده) · دکمهٔ «می‌پذیرم و امضا می‌کنم» · بوم امضای ترسیمی با پیش‌نمایش (PNG شفاف، ≥۳۰۰×۱۵۰) · در ENFORCED دکمهٔ «مخالفم؛ تماس بگیرید» · واژگان صادقانه: «اقرار الکترونیکی شما ثبت شد». در SHADOW برچسب «غیر الزامی — حالت سایه» + «ادامه بدون پذیرش».

### گام ۳ — پرداخت

```text
نام راننده · شمارهٔ بارنامه · مبلغ (ریال)
انتخاب روش:  [پرداخت آنلاین (درگاه)]  [کارت‌به‌کارت]
 ↳ آنلاین: دکمهٔ بزرگ «پرداخت آنلاین» → ریدایرکت → صفحهٔ وضعیت (موفق/ناموفق/UNKNOWN)
 ↳ کارت‌به‌کارت: فهرست گرافیکی کارت‌های فعال سازمان:
     • آیکون و رنگ بانک + نام فارسی بانک (از فهرست ثابت کد — public/banks/{bank_code}.svg)
     • نام و نام خانوادگی صاحب کارت
     • شمارهٔ کارت ۴-۴-۴-۴ + دکمهٔ «کپی»
     • شمارهٔ حساب + دکمهٔ «کپی»
     • شمارهٔ شبا (IR + گروه‌بندی خوانا) + دکمهٔ «کپی»
     • انتخاب کارت مقصد (رادیو)
 فرم اعلام پرداخت: شمارهٔ تراکنش/مرجع (۴-۲۰ رقم) + آپلود تصویر رسید (JPG/PNG/PDF ≤۵MB)
 دکمهٔ بزرگ «پرداخت کردم»
```

- **رفتار کپی:** Clipboard API با مقدار نرمال‌شده (بدون فاصله/جداکننده) + پیام لمسی/متنی «کپی شد» — کاربر کم‌سواد باید مطمئن باشد.
- **رفتار خطای درگاه:** پیام فارسی ساده («پرداخت آنلاین الان ممکن نیست؛ دوباره تلاش کنید یا کارت‌به‌کارت کنید») + کد کوتاه پیگیری؛ UNKNOWN → «در حال بررسی نتیجهٔ پرداخت» + دکمهٔ پرداخت مجدد غیرفعال.
- بعد از تأیید: آنلاین → «پرداخت شما تأیید شد.» + دکمهٔ دانلود فعال · دستی → «ثبت شد و در حال بررسی شرکت است.»
- دکمهٔ دانلود فقط در RELEASED فعال است.

### اصول لمس
کف لمس ≥۴۸px؛ دکمه‌های حساس (ثبت پرداخت، تأیید امضا، دانلود) ≥۵۶px · متن کوتاه و مستقیم · بدون اصطلاح فنی/انگلیسی · شمارهٔ پشتیبانی همیشه پایین صفحه.

### رانندهٔ نیازمند کمک
ثبت به نمایندگی متصدی با برچسب شفاف «این اطلاعات توسط متصدی و به درخواست راننده ثبت شده است»؛ **امضای متصدی هرگز به‌عنوان امضای راننده ذخیره نمی‌شود**.

## پنل داخلی — ۱۷ صفحه

۱. ورود · ۲. داشبورد کارهای در انتظار · ۳. فهرست بارنامه‌ها (فیلتر: شماره/نام/موبایل/تاریخ/وضعیت‌ها) ·
۴. جزئیات بارنامه (۸ بخش: اطلاعات اصلی، راننده/خودرو، مبالغ + تاریخچه + مانده، پنج محور + فاز، PDF، پرداخت‌ها، تعهدنامه/امضا، تاریخچهٔ رخداد + عملیات مجاز) ·
۵. ویزارد Import (آپلود/پیش‌نمایش/خطاها/تأیید) · ۶. بارگذاری و تطبیق PDF · ۷. صف بررسی پرداخت (با زمان انتظار) ·
۸. صف آمادهٔ تحویل · ۹. گزارش‌ها · ۱۰. کاربران و مجوزها (دیالوگ واگذاری) · ۱۱. حساب مقصد و تنظیمات ·
۱۲. نسخه‌های تعهدنامه (پیش‌نمایش با متغیرها) · ۱۳. مرکز اعلان‌ها (ناقوس + شمارنده) ·
۱۴. مانیتورینگ پیامک (ردیف: دلیل فارسی + «ارسال مجدد» + «پیگیری تلفنی») ·
۱۵. تنظیمات مبلغ و نگاشت اکسل · **۱۶. تنظیمات درگاه (۲.۵):** انتخاب ارائه‌دهنده، اعتبارنامه (پس از ذخیره هرگز نمایش نمی‌شود)، حالت آزمایشی/واقعی، دکمهٔ «تست اتصال» + آخرین تست؛ تغییر اعتبارنامه دومرحله‌ای و متوقف در شکست تست ·
**۱۷. کارت‌های واریز (۲.۵):** CRUD گرافیکی + فعال/غیرفعال + ترتیب + **پیش‌نمایش «نمای راننده» با کامپوننت مشترک** — آنچه مدیر می‌بیند همان است که راننده می‌بیند.

### داشبورد
کارت‌ها از **فاز مشتق** محاسبه می‌شوند (هیچ شمارندهٔ مستقل) — کلیک = فهرست فیلترشده: امروز · بدون PDF · **در انتظار پذیرش تعهدنامه (۲.۵)** · منتظر ثبت پرداخت · در بررسی · تأییدشده · **درگاهی امروز (موفق/ناموفق)** · منتظر امضا · تکمیل · خطاهای Import/PDF · **پیامک‌های ناموفق امروز**.

### الگوی داده و رندر
فهرست/جزئیات = Server Components · فرم‌ها = Client + RHF/Zod مشترک · فرم‌های غیرمالی = Server Actions با تأیید دومرحله‌ای · **اقدامات مالی = Route Handler با Idempotency-Key**.

## پنل سلامت فنی (TECH_ADMIN)
فقط: سلامت سرویس‌ها، نسخه، عمق صف، خطاها با شناسهٔ پیگیری، آخرین بکاپ/آزمون restore، فضای دیسک — بدون محتوای حساس.
