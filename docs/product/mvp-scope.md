# دامنهٔ MVP — mvp-scope

> **منبع:** سند مادر v2.5 فصل ۲. هر چیزی که ساخته می‌شود باید به یکی از ردیف‌های
> جدول «داخل MVP» استناد کند؛ ورود هر آیتم فهرست «خارج MVP» به کدِ نسخهٔ اول،
> **خطای دامنه** است.

## داخل MVP

| حوزه | قابلیت |
|---|---|
| شرکت | مشخصات شرکت، حساب دریافت وجه، تنظیمات پایه |
| کاربران | مدیر، سرپرست، متصدی + مجوزهای مستقل قابل واگذاری |
| اکسل | یک قالب تأییدشده با نگاشت ستون، پیش‌نمایش، اعتبارسنجی، گزارش خطا |
| بارنامه | فهرست، جست‌وجو، جزئیات ۸بخشی، تاریخچه، فیلتر |
| PDF | بارگذاری گروهی، تطبیق خودکار/دستی، بررسی تعارض، ذخیرهٔ خصوصی |
| راننده | لینک کوتاه‌عمر، OTP، پورتال موبایل‌محور ۴ گامی |
| تعهدنامه | قالب‌های نسخه‌بندی‌شده با متغیر، پذیرش + امضای ترسیمی — **پیش از پرداخت** (تصمیم ۱۹) |
| پرداخت درگاهی | آداپتر واحد ۶ ارائه‌دهنده (سامان/ملت/پاسارگاد/سداد + زرین‌پال/زیبال)، وریفای server-to-server، تأیید خودکار (تصمیم ۲۰) |
| کارت‌های واریز | CRUD گرافیکی (آیکون بانک/صاحب کارت/کارت/حساب/شبا) + نمایش کپی‌پذیر در پورتال (تصمیم ۲۱) |
| پرداخت دستی | کارت‌به‌کارت/POS/نقد/حواله + «پرداخت کردم» + رسید/شماره تراکنش |
| بررسی پرداخت | صف تصمیم تأیید/رد/مغایرت با دلیل و سابقه |
| اصلاح و بازگشت | لینک مابقی بدون امضای مجدد؛ ثبت بازگشت وجه با تأیید سرپرست |
| تحویل | قاعدهٔ مرکزی canRelease، مجوز تحویل، دانلود امن |
| اعلان | پیامک فراز + ملی‌پیامک (failover) + مرکز اعلان داخلی + پنل ناموفق‌ها |
| گزارش | گزارش‌های عملیاتی و پرداخت + تراکنش‌های درگاهی (به تفکیک ارائه‌دهنده) |
| امنیت | RBAC سمت سرور، rate limit، audit زنجیره‌ای |
| عملیات | بکاپ/restore آزموده، پایش، staging، انتشار، سیاست نگهداری |
| پشتیبانی فنی | داشبورد سلامت بدون دادهٔ حساس (TECH_ADMIN با JIT) |

## خارج از MVP (ممنوع در نسخهٔ ۱)

- استعلام/تطبیق خودکار بانکی و تأیید خودکار تراکنش دستی (۱.۱)
- اتصال POS · صدور خود بارنامه · حسابداری/دفترکل دوطرفه/تسویه جامع
- اپ موبایل native · OCR عمومی · امضای دیجیتال گواهی‌دار (PKI)
- طراحی گردشکار توسط مشتری · پشتیبانی هر قالب اکسل بدون تنظیم
- ثبت‌نام/خرید خودکار چند شرکت · SaaS چندمستاجری کامل
- پیام‌رسان داخلی · چندزبانه · موتور قیمت‌گذاری · BI/داشبورد تحلیلی
- استرداد خودکار درگاهی (Reverse/Refund API) — نسخهٔ ۱.۱+
- حساب دائمی راننده · کد ملی/KYC · دریافت خودکار PDF از سامانهٔ دیگر · پرداخت شرکت به راننده

## مرزهای صریح

1. **گزارش پرداخت سامانه ≠ حسابداری شرکت** — سامانه «ادعا و تأیید پرداخت راننده→شرکت» را ثبت و ممیزی می‌کند؛ دفتر قانونی خارج دامنه است.
2. **MVP کوچک‌تر است، نه کم‌دقت‌تر** — حذف قابلیت مجاز؛ حذف دقت/صحت/ممیزی هرگز. هدف واقع‌بینانه: «دامنهٔ مشخص، بدون بحران امنیتی، پایش خطا، بکاپ قابل‌بازیابی، بازگشت امن از انتشار ناموفق» — نه «صفر باگ».
3. **انتشار** فقط وقتی: زنجیرهٔ کامل با دادهٔ واقعی ≥ یک‌بار اجرا شده + بکاپ واقعاً restore و تست شده + هر ۴۷ معیار acceptance-criteria تأیید شده باشد.

## اعداد کلیدی ظرفیت

- ۲۰۰ بارنامه/روز (≈۷۳k/سال) · ۵۰ نشست هم‌زمان راننده · ۲۰ کاربر داخلی
- Import: ضمانت ۵۰۰ ردیف/دسته؛ سقف پذیرش ۱۵MB/۵۰۰۰ ردیف (بیش از ۵۰۰ = job)
- آپلود ≥۵۰۰ PDF در یک عملیات · PDF هرکدام ≤۱۰MB (پیش‌فرض قابل تنظیم)
- بار ۳ برابری پیک (۱۵۰ نشست / ۶۰۰ بارنامه در روز): فقط کندی تدریجی، بدون خطا/از دست رفتن داده
