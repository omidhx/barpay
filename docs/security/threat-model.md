# مدل تهدید امنیتی — threat-model

> **منبع:** سند مادر v2.5 فصل ۱۰. هر ردیف ماتریس، آزمون متناظر در
> `docs/quality/testing-strategy.md` دارد. نسخهٔ کامل در فاز ۱ گسترش داده می‌شود.

## ماتریس تهدید

| دارایی | تهدید | کنترل | آزمون |
|---|---|---|---|
| دادهٔ بارنامه/پرداخت سازمان | نشت بین‌سازمانی | استقرار + دیتابیس جدا + فیلتر سازمان در همهٔ کوئری‌ها + FK مرکب + Prisma Extension | دسترسی متقاطع دو سازمان |
| رکورد مالی | تکرار/جعل ادعای پرداخت | idempotency دولایه + قید یکتا + هشدار شباهت | تکرار هم‌زمان؛ شماره پیگیری تکراری |
| تاریخچهٔ مالی | دستکاری پس‌رویدادی | audit append-only + زنجیرهٔ row_hash/prev_hash + لنگر off-site هر ۱۵ دقیقه | UPDATE/DELETE روی لاگ |
| سند PDF | دانلود بدون شروط / حدس توکن | canRelease در هر درخواست (گرنت اتمیک) + توکن ≥۱۲۸ بیت هش‌شده | دانلود قبل از تأیید = 403؛ حدس توکن |
| OTP و نشست راننده | brute-force و ارسال انبوه | ۵ تلاش → قفل ۱۵ دقیقه؛ ۳ ارسال/۱۰ دقیقه؛ شمارنده‌های DB-based؛ تعلیق بعد از ۳ قفل در ۲۴ ساعت (`OTP_MOBILE_SUSPENDED`) | ۵ تلاش پشت‌سرهم = قفل |
| مالکیت شمارهٔ راننده | SIM-swap / ATO | **ریسک پذیرفته‌شدهٔ ثبت‌شده با مالک**: OTP تازه در هر ورود + نشست ۲ساعته + تماس تأییدی برای پرونده‌های حساس + واژگان صادقانه (ادعای احراز کامل ممنوع) | زنجیرهٔ OTP→نشست→اقدام در audit؛ هشدار تغییر ناگهانی IP/UA |
| لینک راننده | ارسال مجدد/فرافکنی پیامک | نرخ ۳ در ۱۰ دقیقه + پیام فقط به شمارهٔ ثبت‌شده | درخواست‌های پیاپی |
| تراکنش درگاهی (۲.۵) | callback جعلی/تکراری/مغایرت مبلغ/دو تراکنش هم‌زمان | وریفای server-to-server + مقایسهٔ مبلغ + قید یکتای مرجع + یک تلاش باز | callback جعلی/تکراری؛ مبلغ دستکاری؛ دو init هم‌زمان |
| اعتبارنامهٔ درگاه و کارت‌ها (۲.۵) | سرقت از لاگ/ریپو | AES-256-GCM + ماسک PAN + مجوزهای MANAGE_* | لاگ فاقد اعتبارنامه/PAN کامل؛ پاسخ API فاقد credentials_json |
| دسترسی فنی | سوءاستفادهٔ TECH_ADMIN | JIT با تأیید OWNER (≤۴ ساعت) + ماسک داده + مسیر جانشین MANAGER با DEPUTY_APPROVED | مشاهدهٔ دادهٔ مشتری بدون تأیید = رد |

## حداقل‌های انتشار (۱۵ مورد — بدون هرکدام «قابل انتشار» نیست)

1. HTTPS اجباری
2. احراز هویت امن حساب‌های داخلی
3. 2FA برای مدیران و دسترسی‌های حساس
4. OTP محدود (زمان/دفعات/تلاش)
5. نگهداری امن توکن و کد — بدون مقدار خام در لاگ (HMAC-SHA256 + مقایسهٔ constant-time)
6. لینک دعوت غیرقابل‌حدس و قابل‌ابطال
7. ممنوعیت لینک عمومی دائمی PDF
8. کنترل مجوز در هر درخواست دریافت سند
9. محدودیت اندازه/نوع فایل (magic bytes، نه فقط پسوند)
10. جلوگیری از نشت بین کاربران/شرکت‌ها
11. پاک‌سازی دادهٔ حساس از خطاها و لاگ‌ها
12. ثبت تغییر حساب مقصد/مبلغ/موبایل
13. خروجی اکسل امن در برابر Formula Injection (پیشوند `=` `+` `-` `@`)
14. اسرار خارج از ریپازیتوری (env)
15. اعتبارنامهٔ درگاه فقط رمزنگاری‌شده؛ نتیجهٔ پرداخت فقط از وریفای server-to-server

## امنیت حساب‌ها

- هش رمز: Argon2id (پیشنهادی) یا bcrypt با cost صریح.
- کوکی: `HttpOnly` + `Secure` + `SameSite=Lax`.
- نشست‌های پنل DB-backed (ابطال فوری منفرد/جمعی)؛ انقضا: ۳۰ دقیقه بی‌فعالیتی + ۱۲ ساعت مطلق (قابل تنظیم).
- rate limit: ورود، OTP، مسیرهای لینک، دانلود PDF (۳۰/دقیقه) + per-IP عمومی در Nginx.
- قفل موقت پس از تلاش‌های متوالی؛ پیام ورود همیشه عمومی («شماره یا رمز اشتباه است») — افشای وجود/عدم وجود شماره ممنوع.
- تغییر رمز = خروج از همهٔ نشست‌ها.

## امنیت فایل

- PDF هرگز در مسیر عمومی؛ کلید ذخیره‌سازی `organizations/{orgId}/waybills/{waybillId}/documents/{uuid}.pdf`
- MIME واقعی + magic bytes + ساختار PDF در ingest؛ **PDF دارای JavaScript/اکشن تعاملی کلاً رد** (`PDF_EMBEDDED_JS_DISABLED`) — پاک‌سازی خودکار = آیتم آینده
- حداکثر ۱۰MB (پیش‌فرض قابل تنظیم) · نام تصادفی یکتا · حذف metadata در صورت امکان · اسکن آنتی‌ویروس در صورت امکان · ضد path traversal · هش SHA-256
- **دو محدودیت واقعی مستند:** (۱) ابطال با دانلود endpoint فوری است؛ لینک امضاشدهٔ اختیاری حداکثر تا TTL ۵ دقیقه. (۲) **فایل دانلودشده قابل پس‌گرفتن نیست** — لغو فقط دریافت‌های بعدی را محدود می‌کند (باید در متن تعهدنامه/قرارداد صادقانه بیاید).

## امنیت پرداخت

- رسید = ادعا؛ شماره پیگیری ≠ اثبات انتقال؛ شباهت مبلغ/پیگیری/زمان = هشدار (نه رد خودکار).
- پرداخت درگاهی: عدم اعتماد به query string مرورگر؛ UNKNOWN هرگز FAILED فرض نمی‌شود؛ یک تلاش باز به‌ازای بارنامه؛ PAN ماگسک.
- کارت‌های واریز: نمایش فقط با نشست معتبر راننده یا کاربر مجاز؛ ماگسک در لاگ/گزارش؛ آیکون/نام بانک از فهرست ثابت کد.

## تفکیک دسترسی فنی (TECH_ADMIN)

- JIT: درخواست با دلیل → تأیید OWNER → TTL ≤۴ ساعت → انقضا/ابطال خودکار؛ همهٔ مراحل audit با `tech_admin_access_requests.id` در metadata.
- ماسک داده: موبایل `0912***1234` در لاگ/گزارش؛ کامل فقط صفحات عملیاتی مجاز.
- استقرار روی زیرساخت مشتری: حساب شخصی ثبت‌شده، فقط VPN/SSH تعریف‌شده، بازهٔ محدود، لاگ کامل؛ کلیدهای رمز بکاپ مشتری هرگز به سرورهای ما منتقل نمی‌شود.
- پنل فنی فقط سلامت سرویس‌ها، نسخه، عمق صف، خطاها با شناسهٔ پیگیری، آخرین بکاپ/restore، فضای دیسک — **بدون محتوای حساس**.
